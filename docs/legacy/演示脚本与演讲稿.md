## 三、演示流程（7分钟）

### 第 1 分钟：开场 + 项目概述（60秒）

**展示内容**：首页 `localhost:5173`

**讲稿**：
> 各位评委好。我们带来的作品是「灵山胜境 AI 数字人导游」——一个面向智慧景区的多模态交互导览系统。
>
> 当前景区导览面临三大痛点：导游资源稀缺、传统导览设备无法互动、管理方难以量化游客满意度。
>
> 我们的系统基于大语言模型、RAG 知识检索和 Live2D 数字人技术，为游客提供 7×24 小时智能导览服务，同时为景区管理方提供数据洞察。
>
> 系统采用前后端分离架构——Vue3 前端、FastAPI 后端、PostgreSQL 数据库，AI 能力基于 DeepSeek 大模型和自建 RAG 知识库。

---

### 第 2-3 分钟：游客端核心功能（120秒）

**展示内容**：文本对话 → 数字人讲解 → 语音交互

**操作**：
1. 打开 `localhost:5173/chat`，输入"灵山大佛有多高"，展示流式文字回答 + 来源引用
2. 打开 `localhost:5173/avatar`，看到 Live2D 数字人角色，输入"请介绍一下九龙灌浴"，展示流式文字 + 语音播报 + 嘴型同步
3. 展示表情切换（微笑/专注/惊喜按钮）

**讲稿**：
> 游客可以通过文本和语音两种方式与数字人导游交互。
>
> 【打开对话页，输入问题】首先看文本问答——我输入"灵山大佛有多高"。系统通过 RAG 检索从景区知识库中找到相关资料，结合 DeepSeek 大模型生成回答。注意文字是流式输出的，首字延迟不到 2 秒，游客不用长时间等待。
>
> 【切换到数字人页面】接下来是数字人讲解模式。我们集成了 Live2D Cubism4 模型——这是一个完整的动漫风格导游角色。我输入一个问题"请介绍一下九龙灌浴"，系统做了三件事：RAG 检索 → LLM 生成 → TTS 语音合成 + 数字人口型同步。
>
> 【等待回答播报】大家可以看到数字人的嘴巴是跟随真实音频节奏张合的——我们做了文本预计算口型帧的方案，针对中文的开闭口元音做了专门优化。角色还有微笑、专注、惊喜三种表情可以切换。
>
> 【可选择性展示语音输入】游客也可以直接用语音提问——点击麦克风按钮录音，后端 faster-whisper 模型做语音识别，自动填入输入框。

---

### 第 4 分钟：路线推荐 + 景区地图（60秒）

**展示内容**：路线推荐 → 景区 2D 导览图

**操作**：
1. 打开 `localhost:5173/routes`，展示个性化路线（如"亲子游"路线 + 历史游路线）
2. 打开 `localhost:5173/map`，展示灵山胜境 2D 导览图 + 16 个景点可点击标记

**讲稿**：
> 除了问答，系统还能根据游客的兴趣偏好推荐游览路线。【展示路线页】比如选择"亲子家庭"，系统会推荐适合小朋友的景点组合和游览顺序。
>
> 【打开地图页】这是景区 2D 导览图。我们直接叠加在灵山胜境的官方导览图之上，16 个景点的标记位置是通过坐标校准工具逐一手动标注的，确保精准。点击任意景点可以查看详细介绍、推荐游览时长，还可以一键导航到 OpenStreetMap 或询问 AI 导游。
>
> 地图支持两种模式：官方 2D 导览图和实时地图，后者通过 OpenStreetMap 嵌入，不需要付费地图 Key。

---

### 第 5-6 分钟：管理后台（120秒）

**展示内容**：知识库管理 → 数字人形象配置 → 数据大屏

**操作**：
1. 打开 `localhost:5173/admin/knowledge`，展示文档上传、解析、分块、索引流程
2. 打开 `localhost:5173/admin/avatar`，展示声线切换、语速调节
3. 打开 `localhost:5173/admin/spots`，展示景点管理 CRUD
4. 打开 `localhost:5173/dashboard`，展示服务人次、满意度趋势、热门问答、情感分布
5. 打开 `localhost:5173/feedback`，展示游客反馈收集

**讲稿**：
> 管理后台是景区运营方的核心工具。首先是知识库管理——管理员可以上传景区讲解词、文史资料、常见问题等文档，系统自动解析、智能分块、向量化索引。整个过程是一键完成的，不需要技术背景。
>
> 【展示上传→索引流程】上传后系统自动提取文档内容，按语义切分，生成向量存入 Chroma 知识库，RAG 检索就能即时生效。
>
> 数字人形象管理——管理员可以配置导游的名称、切换声音（晓晓女声、晓伊女声、云希男声），调节语速。Live2D 模型也可以切换不同角色。
>
> 景点管理后台直接对数据库中的景区信息做增删改查。
>
> 【打开数据大屏】这是数据大屏概览——展示景点数量、知识库规模、服务人次、满意度评分、平均响应延迟。下面的情感分布图展示正向/中性/负向反馈比例，热门问题 Top 10 帮助景区了解游客最关心什么。
>
> 游客反馈系统——游客可以对每次问答打分，系统做情感分析后汇总到数据大屏。

---

### 第 7 分钟：技术亮点 + 总结（60秒）

**讲稿**：
> 最后总结我们作品的技术亮点。
>
> 第一，真正的 AI 数字人闭环——从 RAG 知识检索、LLM 推理生成、到 TTS 语音合成、Live2D 口型驱动，全链路打通。不是简单的 API 调用的堆砌，每个环节都做了工程优化。
>
> 第二，面向真实景区场景——基于灵山胜境官方资料构建知识库，16 个景点精确坐标导览，不是演示 Demo 而是可落地的产品。
>
> 第三，完善的降级策略——LLM 不可用时自动回退 RAG 提取模式，TTS 不可用时回退浏览器语音，地图 Key 未配置时回退 CSS 地图，保证系统在任何环境下都能运行。
>
> 第四，工程规范——分层架构、RESTful API、Docker 部署、完整文档，评委可以按 README 一键启动。
>
> 以上就是我们的作品。感谢各位评委。

## 五、录像注意事项

1. **用 OBS 录屏**（免费），不要用 Windows 自带录屏（码率低）
2. **分辨率 1920×1080**，浏览器缩放 125%-150%
3. **先走一遍流程**，熟悉每一步操作，不要录像时到处找按钮
4. **关闭通知、微信、输入法状态栏**
5. **录完检查音频**——确保语音播报被录进去了，不是只有画面
6. **如果某个功能出 bug**：不要停，用备选路径。比如 ASR 不行就跳过语音输入展示，只说"系统也支持语音输入"；RAG 搜不出来就提前准备好一个肯定能命中的问题
