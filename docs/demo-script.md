# 演示脚本

## 演示前准备

1. 启动 Docker Desktop，确认 Linux Engine 正常运行。
2. 在项目根目录执行 `docker compose up --build`。
3. 服务启动后执行 `python scripts/smoke_test.py --base-url http://localhost:8000`。
4. 导入官方景点数据：`python scripts/import_official_data.py --source data/raw/cnsoftbei_a5_official_package.zip --commit`。
5. 在行为数据后台上传 `data/raw/sample_visitor_events.csv`。

## 讲解话术

开场可以直接说：

“这个系统面向灵山胜境游客和景区管理方。游客侧解决‘问得到、听得懂、走得顺’；管理侧解决‘知识可维护、反馈可分析、行为可观察’。”

问答演示时建议使用三类问题：

- 景点事实类：`请介绍灵山大佛`
- 路线建议类：`我只有三小时，想看历史文化景点，怎么走`
- 边界拒答类：`帮我写一段和景区无关的股票分析`

数据大屏讲解时强调：

- 反馈情绪不依赖付费 API，使用本地评分和关键词规则，保证演示稳定。
- 行为事件可以来自前端埋点，也可以由 CSV 导入，适合景区已有离线数据。
- 大屏聚合会话、反馈、收藏、知识库和行为数据，支撑景区运营。

## 异常兜底

| 情况 | 现场说法 |
|---|---|
| 大模型 Key 未配置 | 系统自动使用本地降级回答，保证核心流程不断 |
| 云 TTS Key 未配置 | 浏览器语音合成接管播报 |
| ASR 模型未下载 | 前端提示语音识别不可用，游客可继续文本输入 |
| Docker 未启动 | 先展示前端代码和文档，再启动 Docker Desktop 后执行 smoke test |
| npm/pip 网络异常 | 使用 Docker 构建作为主要交付路径，文档保留本地命令 |
