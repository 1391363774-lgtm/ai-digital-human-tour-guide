# 问答评测说明

> 2026-10-23 更新：下方“既有基线”是历史记录，不代表当前提交。本轮已移除绕过知识库的固定快答/伪来源路径，因此历史模式不可直接比较。100 题没有完整的参考答案、相关片段 ID 和可核查来源标注；Recall@k、MRR、事实与引用支持率目前不可计算。关键词命中仅为代理指标。尚未冻结新的独立语义验收集，也未重新运行完整景区知识库的 100 题；不得把工程回归的通过数写成问答准确率。

## 目标

本轮只读核对仍是 100 题、7 类，未改原题与预期关键词。`data/eval/qa_testset.json` 的 SHA-256 为 `c4344d97e5ea7d72910cf958dc33e1c187467228cec13e645642d3b93580f7f7`。这批题已用于历史调优，不能事后改叫独立盲测集。

这套评测用于回答三个工程问题：

1. 系统能否从知识库取回包含目标景点的片段；
2. 最终回答能否覆盖题目要求的关键事实；
3. 对天气、订票、股票等超出景区知识范围的问题，系统能否明确拒答。

它是面向项目迭代的自动化回归测试，不是通用大模型排行榜，也不能替代人工事实核验。

## 数据集

`data/eval/qa_testset.json` 共 100 题：

| 类别 | 数量 | 主要检查内容 |
|---|---:|---|
| factual | 35 | 高度、年份、材质、数量等可核验事实 |
| intro | 15 | 单个景点的核心介绍 |
| cultural | 10 | 历史和文化背景 |
| comparative | 10 | 两个或多个景点的差异与联系 |
| route | 10 | 不同时长、兴趣和人群的路线建议 |
| paraphrase | 10 | 口语化、指代和同义改写 |
| boundary | 10 | 超范围问题与拒答 |

每题至少包含 `id`、`question`、`category`、`difficulty`、`should_refuse`。非拒答题还可包含：

- `expected_keywords`：需要覆盖的事实或概念；
- `expected_keyword_groups`：同一事实的多种写法，组内命中任意一个即可；
- `spot_names`：检索结果中预期出现的景点名称。

## 指标

- **回答通过率**：按关键词组计算覆盖率，达到 60% 视为通过。纯数字使用数值边界匹配，例如 `9` 不会误命中 `1997`。
- **检索命中率**：返回来源片段是否覆盖该题标注的目标景点。
- **拒答正确率**：`should_refuse=true` 时，接口的 `refused` 标记或明确拒答语句是否成立。
- **分组结果**：按题型和配置分别输出，便于定位是检索、生成还是边界判断的问题。

这些指标的局限包括：关键词命中不代表整段回答没有幻觉；同源知识库与评测题不能证明跨景区泛化；路线建议存在主观性。因此，对外表述应使用“自动评测通过率/检索命中率”，不要简写成“模型准确率”。

## 运行

先启动后端并完成知识库导入、切分和索引，然后执行：

```powershell
python scripts\eval_qa_accuracy.py --base-url http://localhost:8000
```

常用选项：

```powershell
# 前 10 题快速检查
python scripts\eval_qa_accuracy.py --limit 10

# 只比较本地快速回答与 LLM top-k=5
python scripts\eval_qa_accuracy.py --configs fast_topk5,llm_topk5

# 自定义报告路径
python scripts\eval_qa_accuracy.py --output data\eval\my_report.json
```

完整报告包含模型输出，默认视为本地生成物，不提交 GitHub。对外引用结果时应同时记录日期、模型、知识库版本、`top_k` 和评分器版本。

## 既有基线

2026-09-02 使用当前评分器 v2、无云模型的本地快速模式实测结果为：回答通过率 **69%**、检索命中率 **11%**、拒答正确率 **100%**，100 题耗时约 2.5 秒。快速模式会优先返回内置景点摘要且不附检索来源，因此它的检索命中率不适合与 LLM + RAG 配置横向比较；这个配置主要用于检查离线兜底和边界行为。

2026-07-30 的 100 题报告（评分器 v1）记录如下：

| 配置 | 回答通过率 | 检索命中率 | 拒答正确率 |
|---|---:|---:|---:|
| fast_topk5 | 65% | 11% | 90% |
| llm_topk3 | 75% | 92% | 100% |
| llm_topk5 | 75% | 94% | 100% |
| llm_topk8 | 74% | 95% | 100% |

评分器 v2 修复了数字子串误命中和同义写法重复计分问题，因此以上结果只作为历史基线；后续提交前应使用当前脚本重新生成结果，不能直接把旧数字当作新的评测结论。
