# 最小代码助手实验：独立实施任务书

这是三个可靠性修复与 CI 配置完成后准备的实验材料，尚未实现完整 Agent，也没有运行模型 A/B。目的是用小规模、可验收任务学习定位→补丁→测试→diff，先检验实际缺口。

## 固定任务与独立验收

tasks.json 固定20个缺陷快照：D01–D12 共12个开发任务，A01–A08 共8个保留验收任务。每题含问题描述、原始代码和公开示例。acceptance.json 每题另有3个不同输入的独立验收用例，共60个。用户/评测器可审阅 oracle，**模型和工具 sandbox 不得获得整个 bench 目录或 oracle 内容**。

开发任务用于修改 prompt、检索/工具策略与预算。验收任务在协议冻结后一次性比较，不根据验收失败反复调策略再报告同一分数。每题独立工作目录，不在上一个补丁上继续改；公开示例和其他题的原有行为作为回归守卫，拒绝通过修改 tests/TASK.md 或删除功能作弊。

这是小函数 pilot，可能出现两组都全对的天花板效应；不能用它证明大型仓库开发能力。先诚实报告，再建立新版本难度更高的数据集；不可在看完验收结果后偷偷换题。

## 已准备、可直接复现

```powershell
python bench/code_assistant/check_manifest.py --output docs/evidence/reliability/taskset-selfcheck.json
python bench/code_assistant/prepare.py --task D03 --output <全新临时目录>
# 到生成目录执行：
python -m unittest discover -s tests -v
git diff -- src/guide_tools.py
```

prepare 只物化固定的可信初始代码和公开测试，建立本地 Git 基准 commit，拒绝覆盖已有目录。初始测试出现失败是固定故障复现，不能算作代码助手失败。check_manifest 只检查可信数据集：ID/划分/哈希/公开与验收输入不同，以及每个原始快照至少触发一个独立失败；它不是运行未知补丁的安全工具。

## 独立实施边界

在本目录补充 runner，不修改后端可靠性代码；先选 D01 单题跑通。模型编排器在 sandbox 外读取独立环境变量中的 Key，永不复制到小仓库、prompt 日志或容器。代码执行必须在容器或同等隔离环境：非 root、禁网、只挂该题 workspace、限制 CPU/内存/进程数/时限，不挂宿主 Git凭据、Docker socket、整个项目和验收目录。Docker 命令属于未来 runner 的执行设计，本次没有声称已验证该沙箱。

模型只允许固定工具：list/read/rg、对 src/guide_tools.py 应用补丁、运行固定公开测试命令、读 git diff。禁止任意 shell、包安装、网络请求和修改测试。每次工具调用记录入参摘要、退出码、耗时与截断输出；错误退出必须反馈给模型，不能当成功。

验收阶段由独立 evaluator 运行补丁，使用全新容器及只读 oracle；补丁不能写入该目录。验收超时、修改越界、测试改动、空 diff、编译错误、公开回归和验收失败均计失败。执行恶意代码的沙箱设计需要单独验收，不能仅凭 Python subprocess 超时声称安全隔离。

## 两种方案与公平比较

P0：同一模型一次调用，给固定问题、初始代码、公开示例，要求只输出统一 diff；无运行工具与测试反馈。由 evaluator 应用补丁并验收。

P1：同一模型/温度/版本，给相同问题，允许在同一原始小仓库中检索代码、调用允许工具、根据公开测试反馈修补，最后输出 diff。模型不能读取 acceptance.json，也不能用隐藏结果继续修复。这里比较的是整个工作流，不能把差异单独归因于 RAG 或某个工具。

先在12题开发集固定协议，再对8题验收集分别运行 P0/P1。建议首轮每题每组1次、最多6轮工具反馈、120秒墙钟时间和8000输入+输出token总预算；这些是预先设定的实验约束，不是已观察的性能。记录是否超预算，所有尝试都进入分母；API故障也保留，另外统计基础设施错误。不挑选最好的一次。若做多次重复，先固定次数、顺序随机种子和分析规则。

## 每次运行必须保存的真实记录

run_id、task_id、split、taskset/oracle SHA256、模型与API版本、策略版本、原始仓库commit、开始/结束时间、墙钟耗时、轮数、工具调用、公开/独立测试结果、回归数量、diff、越界判断、结束原因、provider返回的输入/输出/缓存token、计费单价来源日期和实际费用。

汇总分别报告开发/保留验收：成功题数/全部尝试题数、回归题数、超时/工具/API错误数量、逐题耗时与median/p95、总token与费用。8题下每多一题会改变12.5个百分点，样本很小；必须同时给计数，不能只宣传百分比。provider没返回用量或无账单时标记 unavailable，不估造成“真实消耗”。源码差异、隐藏测试和原始日志一起留给独立审阅者。
